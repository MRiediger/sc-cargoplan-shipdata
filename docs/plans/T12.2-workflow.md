### 1 – `nothingChanged` (D2, P4) – `diff.py`, `stages.diff_stage`, `stages.verify_stage`

- `diff.json` trennt `ships.gone` (**neu** verschwunden: im Vorgänger ohne `missingSince` und ohne `follows`) von `ships.stillGone`. `verify` gibt `rules.missing` beide Listen (Fortschreibung von `missingSince`/`follows` bleibt).
- `nothingChanged` = keine geänderten/neuen Schiffe, keine neu Verschwundenen, kein **wieder da**, keine geänderten/neuen Modelle, keine Import-Status `order`/`handcheck`.
- Tests (`test_diff.py`/`test_pipeline.py`): Vorgänger mit Cyclone `missingSince` + Variante `follows`, Katalog unverändert → `nothingChanged` true · ein neu Verschwundener → false · wieder da mit gleichem Inhalt → false · Reihenfolge vertauscht → false. ### 3 – `run.py previous`

### 4 – `run.py draft` und `run.py publish`

- **draft** (Ende der Kette, und für den Seed mit `--folder out/seed --tag ships-2026.11`): `release.pack` → veraltete Entwürfe löschen (+ deren PR schließen, Kommentar „superseded by …“) → `gh release create <tag> --draft --target <sha> --title <tag> --notes-file …` → Holos, `ships.zip`, `NOTICE.md` hochladen → **`manifest.json` zuletzt**. Output `tag`.
- **publish** (`--tag` oder `--pending state/pending.json`): Assets des Entwurfs gegen sein Manifest (Namen, Größen, `digest`, falls `gh` ihn liefert – A3 prüfen), bei `--pending` Manifest-SHA = `pending.json` → Kontaktabzug-Assets löschen → `gh release edit <tag> --target <sha> --draft=false --latest` → Hygiene (`gh release delete <tag> --cleanup-tag --yes`) → Prune (P8). Ersetzt `release.publish`.
- `gh`-Flags gegen `gh 2.102` geprüft (A3, `gh release create/edit/upload/delete --help`): `--draft`, `--target`, `--latest`, `--notes-file`, `--draft=false`, `--clobber`, `--cleanup-tag`. Hinweis der Hilfe: „Immutability is enforced only after a release is published“ – ist Release-Immutability im Repo an, kann die Hygiene alte Tags nicht löschen → in Block 10 die Repo-Einstellung prüfen, Befund statt Annahme.
- Tests: Reihenfolge der `gh`-Aufrufe (Manifest-Upload nach allen anderen, `--draft=false` nach allen Uploads) · Manifest-SHA ≠ `pending.json` → Abbruch ohne `edit` · Hygiene löscht genau das dritte · Prune behält die Modelle des Manifests.

### 5 – `run.py heartbeat`

- Liest `NEEDS` (`${{ toJSON(needs) }}`, Ergebnisse + Outputs aller Jobs) und die Berichte; schreibt `state/last-run.json`: `date`, `runId`, `runUrl`, `event`, `result` (`release | pr | nothing | error | gate-red`), `dataVersion`, `previous`, `line`, `stages {name: {checked, found, todo}}` (aus `out/say.jsonl`, das `Reporter.say` neu mitschreibt). Bei `publish-merged` zusätzlich `git rm state/pending.json`. Commit `data: heartbeat <date> – <line>` als `github-actions[bot]`, `git pull --rebase` einmal, Push.
- **Schlusszeile** `summary_line(...)`, Test je Pfad: „Release ships-2026.11.1: 1 ship changed, 1 new, 96 holos refreshed“ · „PR #12: 2 findings“ · „nothing changed“ · „error in build: …“ · „gate red: 3 ships differ unexpectedly“. *holos refreshed* = neu gebaut und nicht byte-gleich zum Vorgänger.
- Tests: jede Ergebnisart, `pending.json` wird nur bei `publish-merged` entfernt.

### 6 – `run.py pr`

- **PR-Text nur aus Feldern** (`verify.json` E1, `diff.json`, `gate.json`): Kopf mit Schlusszeile und Link zum Lauf; **Tabelle je Stopp**: Schiff · Regel/SD5-Fall(e) · Modell alt → neu · `passed` alt → neu · `fails` · Hausdorff alt → neu (Δ, Toleranz) · Dreiecke / Budget; Gate (gleich / anders / unerwartet 0); Link zum Entwurfs-Release mit dem Kontaktabzug; Hinweise als eingeklappte Liste mit Zahl; „Merge = Freigabe: der Entwurf `<tag>` wird unverändert veröffentlicht“.
